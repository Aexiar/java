# 第一章：简介

## 1.1 Linux 中的软件包管理器

* 如果你玩过 Linux，一定对 Linux 中的软件包管理器并不陌生，如： `apt` 和 `dnf` 等，其主要目标是用来 `解决依赖管理，简化软件包的安装` 。

![Linux 中的软件包管理器](https://github-pic.oss-cn-hangzhou.aliyuncs.com/linux/2026-03-25/2026-03-25-08-33-45.png)

## 1.2 Windows 中的软件包管理器

* Windows 操作系统本身就是以 `图形用户界面（GUI）` 为主，早期大多数人都是通过鼠标下一步来安装软件包，Windows 上的软件包的格式通常是 `.exe` 、 `.msi` 以及 `.zip` ，一旦软件包更新之后（新版本的推出），还需要用户重新下载并进行安装，以便体验最新的功能。

![Windows 操作系统早期软件包的安装](https://github-pic.oss-cn-hangzhou.aliyuncs.com/linux/2026-03-25/2026-03-25-08-35-50.png)

* 但是，随着时间的发展，Windows 社区吸收了 Linux 社区的思想，将软件包管理器也带入了 Windows 中，这样在 Windows 中我们也可以通过命令行来安装软件包。

> [!NOTE]
>
> * ① 软件包管理器是 Windows 的附加工具，用户可以选择使用，也可以直接通过网页或商店安装软件包。
> * ② 在 Windows 11、Windows 10 1709（版本 16299）或更高版本上以及 Windows Server 2025 中，Windows 开箱支持 WinGet 程序包管理器。

* Linux 中的软件包管理器有多种，如： `dnf` 和 `apt` 等，Windows 也不例外，如下所示：
    * ① `winget（Windows Package Manager）` ：Windows 官方支持，非常稳定。
    * ② `Chocolatey` ：社区支持，但是维护的大量的软件包。
    * ③ `Scoop` ：社区支持，主打轻量化。
    * ④ `Ninite` ：一次性安装并更新所有程序（如果你不熟悉命令行，可以选择该工具）。

* Windows 软件包管理器的特点，如下所示：

| Windows 软件包管理器 | 特点                                                         |
| -------------------- | ------------------------------------------------------------ |
| winget               | ① 官方提供，由微软开发。<br>② 命令行工具，可以快速安装、升级和卸载软件。<br>③ 包含常见的第三方软件包。 |
| Chocolatey           | ① 长期流行的第三方软件包管理器。<br>② 支持许多开发工具、服务和常见软件。<br/>③ 提供商业版支持。 |
| Scoop                | ① 专注于开发者工具，如：编程语言、数据库等。<br>② 无需管理员权限即可安装。<br>③ 使用简洁，易于扩展。 |
| Ninite               | ① 简单易用，适合普通用户。<br>② 自动化安装和更新常见软件，如：浏览器、媒体播放器等。 |



# 第二章：winget（🔥）

## 2.1 概述

* 开发人员可以使用 `winget` 命令行工具发现、安装、升级、删除和配置特选应用程序集。
* 安装后，开发人员可以通过 Windows 终端、PowerShell 或命令提示符访问 `winget` 。

## 2.2 工作原理

### 2.2.1 概述

* `winget` （Windows Package Manager）是微软官方推出的 Windows 命令行软件包管理工具。
* 它的核心设计理念是 `作为系统原生安装程序的“调度器”和“清单管理器”` ，而不是自己去实现一套复杂的软件安装逻辑。

### 2.2.2 核心架构（清单（Manifest）驱动）

* `winget` 本身不包含任何软件的实体文件，它完全依赖于 `清单文件（Manifests）` ，如下所示：

::: details 点我查看清单文件的具体细节

* ① 清单格式：清单是基于 YAML 格式的文本文件。
* ② 包含内容：软件名称、版本号、下载 URL、**SHA256 哈希值**、安装程序类型（MSI, EXE, MSIX 等）、以及**静默安装参数**（如 `/S` , `/quiet` , `/VERYSILENT` ）。 
* ③ 数据源：默认情况下， `winget` 连接的是微软托管在 GitHub 上的开源仓库 `microsoft/winget-pkgs` 。社区和软件开发者通过提交 PR（Pull Request）来更新或添加这些 YAML 清单。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/linux/2026-07-13/2026-07-13-19-43-48.png)

### 2.2.3 工作流程

* 当我们在终端输入 `winget install <软件包>` 的时候，底层会经历以下流程，如下所示：

::: details 点我查看具体细节

* `A. 搜索与索引匹配` ：

  * ① **本地缓存查询**： `winget` 客户端首先会查询本地的 SQLite 数据库缓存，看是否有匹配的清单。
  * ② **远程同步**：如果本地没有或缓存过期，客户端会通过 REST API（或 GitHub API）向远程源（Source）请求最新的索引数据，并更新本地缓存。 

* `B. 下载与安全检查（核心安全机制）` ：

  * ① **获取下载链接**：从匹配的 YAML 清单中提取安装包的下载 URL。
  * ② **下载文件**：将安装包（.exe, .msi, .msix 等）下载到系统的临时目录（通常是 `%TEMP%\WinGet` ）。
  * ③ **哈希校验**：下载完成后， `winget` 会计算该文件的 **SHA256 哈希值**，并与清单中声明的哈希值进行严格比对。**如果不一致，安装会立即中止**。这确保了下载的文件没有被篡改或损坏。

* `C. 执行安装（调度器角色）` ： `winget` 本身**不负责**解压、释放文件或写入注册表（便携版 ZIP 除外），它是 `调用 Windows 原生的安装机制` 。

  | 文件类型                    | 描述                                                         |
  | --------------------------- | ------------------------------------------------------------ |
  | MSI 文件                    | 调用系统自带的 `msiexec.exe` ，并附加清单中定义的静默参数。   |
  | MSIX / APPX 文件            | 调用 Windows 的 MSIX 部署 API 进行沙盒或系统级安装。         |
  | EXE 文件                    | `winget` 会读取清单中针对该特定安装程序预设的“静默安装开关（Silent Switches）”，然后直接执行该 EXE。 |
  | ZIP 文件（Portable 便携版） | 只有对于标记为 `portable` 的 ZIP 包， `winget` 才会自己将其解压到指定目录（如 `%LOCALAPPDATA%\Microsoft\WinGet\Packages` ），并自动将其加入系统的 `PATH` 环境变量。 |

* `D. 状态追踪与验证` ：安装程序运行结束后， `winget` 需要确认软件是否真的安装成功了

  * ① **读取 ARP**： `winget` 会扫描 Windows 的“添加或删除程序”（Add/Remove Programs, ARP）注册表项。
  * ② **匹配产品代码**：它会将清单中声明的 `ProductCode` （针对 MSI）或 `Display Name` 与 ARP 中的记录进行匹配。如果找到了对应记录，则认为安装成功，并将其记录到 `winget` 本地的 `installed.db` 数据库中。

::: code-group

```powershell 
Register-ArgumentCompleter -Native -CommandName winget -ScriptBlock {
    param($wordToComplete, $commandAst, $cursorPosition)
        [Console]::InputEncoding = [Console]::OutputEncoding = $OutputEncoding = [System.Text.Utf8Encoding]::new()
        $Local:word = $wordToComplete.Replace('"', '""')
        $Local:ast = $commandAst.ToString().Replace('"', '""')
        winget complete --word="$Local:word" --commandline "$Local:ast" --position $cursorPosition | ForEach-Object {
            [System.Management.Automation.CompletionResult]::new($_, $_, 'ParameterValue', $_)
        }
}
```

### 2.4.1 搜索软件

* 格式：

```shell
winget search [可选参数] [-q] <软件名> 
```

> [!NOTE]
>
> 参数：
>
> * `-q、--query` ：查询标志是用于搜索应用的默认参数。无需指定。
>
> 可选参数：
>
> * `--id` ：将搜索限制为应用程序的 ID。该 ID 包含发布者和应用程序名称。
> * `--name` ：将搜索限制为应用程序的名称。
> * `-s、--source` ：使用指定的源名称（msstore 等）查找包。
> * `--versions` ：显示程序包的可用版本。



* 示例：查询指定的软件包

# 第四章：Scoop（🔥）

## 4.1 概述

* [Scoop](https://scoop.sh/) 是 Windows 平台上一个非常强大的 `命令行包管理器` （Package Manager）。简单来说，它就像是 Linux 里的 `apt` / `yum` ，或者 macOS 里的 `Homebrew` 。
* 我们可以用一行命令来安装、更新、卸载软件，而不需要去各种官网找下载链接、点“下一步”安装包。

## 4.2 Scoop 和 winget 的区别

### 4.2.1 为什么使用 Scoop？

* 普通的 Windows 软件安装经常让人头疼：权限弹窗、环境变量手动配置、各种流氓软件捆绑、卸载不干净。
* scoop 正式为了解决这些痛点而生的，特别是对 `开发者` 极其友好：

| 优点                         | 描述                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| :one: `免管理员权限`         | 默认将软件安装在你的用户目录（ `C:\Users\用户名\scoop` ）下，安装时不会弹出 UAC 账户控制提示。 |
| :two: `不污染系统环境`       | 软件彼此隔离，所有的环境变量（ `PATH` ）都由 Scoop 自动配置和管理，不会弄乱注册表。 |
| :three: `真正的“绿色版”体验` | Scoop 倾向于下载解压即可用的便携版（Portable）软件。<br>卸载时直接删掉对应文件夹，不留任何垃圾。 |
| :four: `极简版本切换`        | 可以同时安装 Java 8、Java 11 和 Java 17，用一行命令就能在它们之间无缝切换。 |

### 4.2.2 Scoop vs WinGet 

* 两者都是 Windows 下的包管理器，但它们的 `设计哲学和受众` 完全不同，如下所示：

| 特性              | Scoop                                              | WinGet                                                |
| ----------------- | -------------------------------------------------- | ----------------------------------------------------- |
| :one: 官方背景    | `开源社区驱动`                                     | 微软官方出品（Win11 自带）                            |
| :two: 核心定位   | `面向开发者` ，偏向命令行工具、开源软件和绿色版软件 | `面向普通大众` ，偏向传统 GUI 软件（QQ、微信、Office） |
| :three: 安装方式  | 解压/便携化（Portable），安装在用户目录            | 运行官方的 `.exe` 或 `.msi` 安装包                    |
| :four: 管理员权限 | `默认不需要`                                       | 大多数情况下需要（会弹出提示）                        |
| :five: 环境变量   | `自动配置，且管理得井井有条`                       | 依赖软件安装包自带的配置，有时需要手动调              |

> [!TIP]
>
