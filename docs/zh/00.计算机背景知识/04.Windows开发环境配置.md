## 1.2 替换 winget 源和 scoop 源

### 1.2.1 概述

* 默认的 winget 源或 scoop 源很慢，需要替换为国内源。

### 1.2.2 winget 源替换

* 默认的 winget 源很慢，可以替换为国内源：

```powershell
# 先删除较慢的官方 winget 源
winget source remove winget
# 将中科大的镜像源添加进去，并取名为 winget
winget source add winget https://mirrors.ustc.edu.cn/winget-source --trust-level trusted
# 刷新并检查
winget source update
winget source list
```

> [!NOTE]
>
> * ① 修改 WinGet 软件源需要管理员权限，请以管理员身份运行终端。对于 [启用 sudo](https://learn.microsoft.com/windows/advanced-settings/sudo/#how-to-enable-sudo-for-windows) 的 Windows 11 用户，也可以使用 `sudo` 进行提权。
> * ② 重置为官方地址，可以使用如下的命令：
>
> ```powershell
> winget source reset winget
> ```



* 示例：

::: code-group

```powershell
winget source remove winget
winget source add winget https://mirrors.ustc.edu.cn/winget-source --trust-level trusted
winget source update
winget source list
```

### 1.2.3 Scoop 源替换

* 默认的 scoop 源很慢，可以替换为国内源：

```powershell
# 先删除较慢的官方 scoop 源
scoop bucket rm main
scoop bucket rm extras
scoop bucket rm versions
scoop bucket rm nerd-fonts
scoop bucket rm nonportable
scoop bucket rm nirsoft
scoop bucket rm java
# 替换为国内镜像源
scoop bucket add main https://mirror.nju.edu.cn/git/scoop-main.git
scoop bucket add extras https://mirror.nju.edu.cn/git/scoop-extras.git
scoop bucket add versions https://mirror.nju.edu.cn/git/scoop-versions.git
scoop bucket add nerd-fonts https://mirror.nju.edu.cn/git/scoop-nerd-fonts.git
scoop bucket add nonportable https://mirror.nju.edu.cn/git/scoop-nonportable.git
scoop bucket add nirsoft https://mirror.nju.edu.cn/git/scoop-nirsoft.git
scoop bucket add java https://mirror.nju.edu.cn/git/scoop-java.git
# 刷新测试
scoop update
```

> [!NOTE]
>
> * ① 可以使用如下的命令，切换 scoop 核心源：
>
> ```powershell
> scoop config scoop_repo https://mirror.nju.edu.cn/git/scoop.git
> ```
>
> * ② 从国内源恢复至官方源：
>
> ```powershell
> scoop bucket rm main
> scoop bucket rm extras
> scoop bucket rm versions
> scoop bucket rm nerd-fonts
> scoop bucket rm nonportable
> scoop bucket rm nirsoft
> scoop bucket rm java
> 
> scoop bucket add main
> scoop bucket add extras
> scoop bucket add versions
> scoop bucket add nerd-fonts
> scoop bucket add nonportable
> scoop bucket add nirsoft
> scoop bucket add java
> ```



* 示例：

::: code-group


```powershell
# 激活
# ① 创建目录
# PowerShell 5.1 用户
if (!(Test-Path "$HOME\Documents\WindowsPowerShell")) {
    New-Item -Path "$HOME\Documents\WindowsPowerShell" -ItemType Directory
}
# PowerShell 7+ 用户
if (!(Test-Path "$HOME\Documents\PowerShell")) {
   New-Item -Path "$HOME\Documents\PowerShell" -ItemType Directory
}

# ② 写入 mise 初始化命令
# PowerShell 5.1 用户
"`n`$env:MISE_PWSH_CHPWD_WARNING = 0" | Add-Content $PROFILE
'(&mise activate pwsh) | Out-String | Invoke-Expression' | Add-Content -Path "$HOME\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1"
# PowerShell 7+ 用户
"`n`$env:MISE_PWSH_CHPWD_WARNING = 0" | Add-Content $PROFILE
'(&mise activate pwsh) | Out-String | Invoke-Expression' | Add-Content -Path "$HOME\Documents\PowerShell\Microsoft.PowerShell_profile.ps1"

# ③ 验证配置文件内容
notepad $PROFILE  # (&mise activate pwsh) | Out-String | Invoke-Expression

# ④ 重新加载配置
. $PROFILE
```

## 3.1 安装

### 3.1.1 安装 Hyper-V

* Hyper-V 是 Microsoft 内置于 Windows Server 和 Windows 中的企业级虚拟机管理程序技术，其提供硬件虚拟化功能，使组织能够大规模创建、管理和运行虚拟机。 
* 作为一级虚拟机监控程序，Hyper-V 直接在计算硬件上运行，为虚拟工作负载提供近乎本地化性能和强大的隔离。

> [!NOTE]
>
> * ① 系统限制 & 硬件要求：
>
> | 系统限制 & 硬件要求 | 描述                                                         |
> | ------------------- | ------------------------------------------------------------ |
> | 系统限制            | 仅内置于 Windows `专业版` 、 `企业版 ` 和 `教育版` 中，即：如果使用的是 Windows 家庭版，默认是无法直接开启的（需要通过脚本破解或升级系统）。 |
> | 硬件要求            | 电脑 CPU 必须支持硬件虚拟化（Intel VT-x 或 AMD-V），且内存建议至少 8GB 以上（因为虚拟机需要共享电脑的实际内存）。 |
>
> * ② 安装完毕之后，可能会提示重启计算机，那就按照提示重启计算机！！！

### 3.2.4 WSL 中的高级设置

* `wsl.conf` 和 `.wslconfig` 文件用于在 WSL 中配置高级设置，这些设置将在 WSL VM 启动时应用。
* `wsl.conf` VS `.wslconfig` ，如下所示：

| 方面  | `.wslconfig`                                                 | `wsl.conf`                                                   |
| :---- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| Scope | 适用于所有 WSL 的常规设置                                    | 仅限 WSL 分发的设置                                          |
| 配置  | WSL 中的功能启用、为 WSL 2 提供支持的虚拟机设置（RAM、要启动的内核、CPU 数等） | WSL 中的分发设置，例如启动选项、DrvFs 自动装载、网络、与 Windows 系统的互作性、系统使用情况和默认用户 |
| 位置  | `%UserProfile%\.wslconfig` ，在 WSL 分发之外                  | `/etc/wsl.conf` ，而在 WSL 分发中                             |

> [!NOTE]
>
> * ① `wsl.conf` 用于根据 WSL 发行版应用设置； `.wslconfig` 用于将全局设置应用于 WSL。
> * ② 可以通过 `WSL Settings` 软件，来修改 `.wslconfig` 配置文件。
>
> ::: details 点我查看细节
>
> ![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/linux/2026-07-09/2026-07-09-13-27-24.png)
>
> :::
>
> * ③ 修改配置文件后，需要使用 `wsl --shutdown` 重启 WSL2 中的 Linux 发行版。



* 示例：修改 `.wslconfig` 文件

::: code-group

```bash [git-bash]
cat > ~/.wslconfig <<-'EOF'
[wsl2]
# ==========================================
# 1. 基础性能与硬件资源限制
# ==========================================

# 限制 WSL2 最多能使用的内存大小。防止 Linux 占用过多内存导致 Windows 宿主机卡顿
# （可根据电脑配置调整，例如：16GB 内存建议设为 8GB~12GB）
memory=12GB

# 限制 WSL2 最多能使用的 CPU 核心数。
# 防止 Linux 在满载运行时（如编译代码）让 Windows 彻底卡死
processors=6

# 开启嵌套虚拟化。
# 允许你在 WSL2 内部再运行一层虚拟机，如：在 WSL 里面玩 KVM 或高级 Docker 容器
nestedVirtualization=true

# ==========================================
# 2. 现代高级网络模式（让 WSL 拥有原生网络体验）
# ==========================================

# 开启镜像网络模式。
# 让 WSL2 完全共享 Windows 的网络栈和 IP 地址，解决绝大多数因网络隔离导致的连接问题
networkingMode=mirrored

# 允许 Windows 防火墙规则直接应用到 WSL2 中，大幅增强 Linux 环境的网络安全性
firewall=true

# 开启 DNS 隧道。
# 由 Windows 代理 WSL 的 DNS 请求，彻底解决 Linux 无法解析域名或 DNS 污染的问题
dnsTunneling=true

# 自动同步代理。
# 自动将 Windows 宿主机的系统代理同步给 WSL2，Linux 内部无需再手动配环境变量
autoProxy=true

# 允许 WSL 内部使用 IPv6（需要你本地的宽带和路由器支持 IPv6 才能真正生效）
ipv6=true

# 闲置超时自动关机。
# 当所有 WSL 窗口关闭且没有后台任务时，闲置 1 分钟后整个 WSL 虚拟机会自动彻底关闭
vmIdleTimeout=60000

# ==========================================
# 3. 实验性功能与资源自动回收
# ==========================================
[experimental]

# 自动释放 Linux 缓存内存。
# 当 Linux 内部闲置时，会自动把占用的 RAM 内存归还给 Windows
autoMemoryReclaim=dropCache

# 磁盘自动瘦身。
# 当在 Linux 中删除文件后，Windows 会在后台自动压缩并减小 ext4.vhdx 虚拟硬盘的体积
# （注意：现有子系统需要去运行 wsl --manage <分发版名称> --set-sparse true）
sparseVhd=true

EOF
```

# 第四章：Docker Desktop

## 4.1 概述

* `Docker Desktop` 是一款专为 Mac、Windows 以及 Linux 环境打造的桌面应用程序。

> [!NOTE]
>
> * ① 简单来说，Docker 本身是基于 Linux 内核的容器技术。为了让开发者在 Windows 系统上也能流畅地使用 Docker，官方推出了 Docker Desktop。
> * ② 它集成了一个图形化管理界面（GUI）以及完整的 Docker 核心工具（Docker Engine、Docker CLI、Docker Compose 等）。

* 在传统开发中，你可能经常遇到“在我的电脑上明明运行得好好的，怎么到你那里就报错了”的窘境，而 Docker 就是为了解决这个问题而生的：

| 特点               | 描述                                                         |
| ------------------ | ------------------------------------------------------------ |
| `消除环境差异`     | 它可以将你的应用程序及其所依赖的环境（如特定的数据库、Node.js 版本、系统配置文件等）打包进一个叫“镜像（Image）”的压缩包中。<br>无论在谁的电脑或服务器上运行，只要有 Docker，就能一键跑起来，且表现完全一致。 |
| `轻量级虚拟化`     | 与传统虚拟机（如 VMware、VirtualBox）相比，Docker 容器不需要为每个实例运行一个完整的操作系统。<br/>它与宿主机共享内核，因此启动只需几秒钟，占用的 CPU 和内存极少。 |
| `一键部署复杂环境` | 当我们想在本地装个 MySQL、Redis 或 Nginx，不再需要繁琐地去官网下载、配置环境变量。<br>只需一条命令（如 `docker run` ），Docker 就会自动帮你下载并秒级启动。 |
| `环境隔离`         | 不同的项目可以用不同的容器，哪怕一个要用 Python 2.7，另一个要用 Python 3.11，它们在各自的容器里互不干扰，不会搞脏 Windows 主机系统。 |
